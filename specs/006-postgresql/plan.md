# Implementation Plan: Kravændring – PostgreSQL i stedet for MySQL

**Branch**: `006-postgresql` | **Date**: 2026-11-03 | **Spec**: [spec.md](spec.md)

## Summary

Kunden har ændret T1: databasen skal være PostgreSQL. Skiftet holdes i datalaget og
infrastrukturen: `docker-compose.yml`, `.env.example`, `db/`, `backend/src/db.js`,
`backend/src/repositories/` og testdatabasen. Services, routes, frontend, OpenAPI og Tableau
ændres ikke (A5, A6). Samtidig gennemgås indekser og langsomme forespørgsler (FR-010, FR-011).

## Technical Context

**Language/Version**: Node.js 24 (ES modules), Express 5
**Primary Dependencies**: `pg` 8 (node-postgres) erstatter `mysql2`. Ingen andre nye pakker.
**Storage**: PostgreSQL 18 (`postgres:18`) med named volume `pg-data`
**Testing**: `node:test`, `docker compose exec backend npm test`
**Performance Goals**: SC-005: navnesøgning og første side af bookinglisten under 200 ms
**Constraints**: Samme API-svar som før (byte for byte på startdatasættet), fremlæggelse 2026-11-06

## Beslutninger

| # | Beslutning | Begrundelse | Fravalgt |
|---|---|---|---|
| R1 | `pg` (node-postgres) med rå, parametriseret SQL | Mest udbredte driver, samme model som `mysql2` (pool, `query`, transaktioner) | ORM (constitution), `postgres.js` (tagged templates ville kræve omskrivning af alle dynamiske WHERE-byggere) |
| R2 | Repositories beholder `?`-pladsholdere. `query()` i `db.js` nummererer dem til `$1, $2 …` | WHERE-byggerne i `bookingRepository` og `barRepository` sammensætter betingelser dynamisk. Med `?` behøver de ikke tælle. Én funktion på fem linjer, ét sted | Skrive `$n` i hver repository: flere linjer og let at tælle forkert |
| R3 | `DATE` og `TIMESTAMP` læses som strenge, `BIGINT` som `Number` (type-parsere i `db.js`) | Samme som `dateStrings: true` i `mysql2`, så en tidszone aldrig flytter en ankomst. `COUNT(*)` er `BIGINT` i PostgreSQL | Konvertere i hver repository |
| R4 | `TIMESTAMP(0)` og `LOCALTIMESTAMP(0)` med `TZ=Europe/Copenhagen` på db-containeren | Hele sekunder i dansk lokaltid, som `DATETIME` gav før. `initdb` tager tidszonen fra `TZ` | `TIMESTAMPTZ`: ville ændre API-formatet |
| R5 | Navnesøgning: `search_key()` = `lower(unaccent(…))` + GIN-trigramindeks (`pg_trgm`) | Erstatter MySQL's `utf8mb4_0900_ai_ci` (store/små bogstaver og accenter ignoreres, 001 FR-002), og `LIKE '%…%'` kan nu bruge et indeks | ICU-collation uden determinisme: `LIKE` virker først fra PG 18 og kan ikke bruge et B-tree |
| R6 | `GENERATED BY DEFAULT AS IDENTITY`, og seed-scriptet kalder `setval` efter faste id'er | Seedet indsætter faste id'er. Uden `setval` ville næste booking fra API'et få et id, der er i brug | `SERIAL` (ældre syntaks), `GENERATED ALWAYS` (afviser faste id'er) |
| R7 | `source` som `VARCHAR` + `CHECK (source IN …)` i stedet for `ENUM` | PostgreSQL har ingen kolonne-`ENUM`. `CHECK` er den simpleste regel (`database.md` §2) | `CREATE TYPE … AS ENUM` |
| R8 | Nyt volume-navn `pg-data` | Et gammelt MySQL-volume bliver aldrig mountet i PostgreSQL, og ingen data slettes ved skiftet | Genbruge `db-data` og kræve `docker compose down -v` |
| R9 | Testdatabasen oprettes af `test/testDb.js` med `DROP DATABASE … WITH (FORCE)`. `db/00_test-db.sh` slettes | `POSTGRES_USER` ejer serveren og må oprette databaser, så init-scriptet er overflødigt | Beholde et shell-script i `db/` |
| R10 | Indekser på fremmednøgler i `bookings` og `bar_sales` | PostgreSQL indekserer ikke fremmednøgler selv, som MySQL gjorde. Uden `bar_sales(booking_id)` læser sletning af en booking alle barsalg | Indeks på alle fremmednøgler: `rooms` (214 rækker, 2 sider) og opslagstabellerne bliver altid læst helt (EXPLAIN, 0 indeksopslag over et helt snapshot) |
| R11 | `ANALYZE` sidst i `02_seed.sql` | Autovacuum analyserer først en tabel efter ca. 50 ændrede rækker, så de små tabeller fik aldrig statistik, og barsalg pr. drink sorterede på disk (61–82 → 36 ms) | Vente på autovacuum |
| R12 | Fælles `stayCalendar()` i `services/pricing.js` til BI og omsætning | Ca. 1,3 mio. værelsesnætter ligger på få tusind datoer. At formatere hver nats dato og finde dens sæson igen var det meste af svartiden. Ét sted, så de to services ikke har hver sin kopi | Cache på tværs af requests (constitution VI, A4) |
| R13 | Cifersøgning: `b.room_id = (SELECT …)` i stedet for `IN (SELECT …)` | `room_number` er unik. Med `=` kan PostgreSQL kombinere navneindeks, primærnøgle og `room_id`-indeks (BitmapOr): 89 → 1 ms | – |

SQL-oversættelsen i repositories: `DATEDIFF(a, b)` → `a - b`, `DATE_ADD(?, INTERVAL 1 DAY)` →
`?::date + 1`, `DATE_FORMAT` → `to_char`, `DATE(x)` → `x::date`, `IN (?)` med array → `= ANY(?)`,
`ON DUPLICATE KEY UPDATE` → `ON CONFLICT … DO UPDATE`, `insertId` → `RETURNING id`,
`affectedRows` → `rowCount`, camelCase-aliaser i dobbelte anførselstegn.
